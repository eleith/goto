# Philosophy

GoTo is for the short links I keep. I built it for myself and other self-hosters whose links are mostly stable shortcuts, not hundreds of randomly generated URLs.

The important part is the link itself: its name, where it goes, and the rules it follows. That belongs in a text file I can read, back up, and restore. SQLite stores visit counts and analytics, not the link definitions. The admin shows what’s configured without becoming a second place to edit it. It can use the sign-in system I already run.

I want GoTo to be simple, fast, and readable, without asking a small self-hosted setup to run more than it needs. Those tradeoffs are the point.

If you need an API, integrations, or a shortener that scales, use [Shlink](https://shlink.io/). It’s the best self-hosted shortener for that job, hands down. GoTo is for a smaller job.
